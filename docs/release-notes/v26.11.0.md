## TcpTools 26.11.0

The client, the server and the relay are now **one program**: `TcpTools.exe`, one window, one tab per tool.
Unzip and run — there is nothing to install.

### New

- **Tabs.** The program opens with a Client, a Server and a Relay tab. The **+** tab (Ctrl+T) adds more of
  any kind, so several clients, servers and relays run side by side; a right-click, a middle-click or
  Ctrl+W closes a tab. Ctrl+Tab switches, F1 opens the help of the tab in front.
- **Every tab tells what it is doing** while another one is in front: a state dot (grey idle, amber
  waiting, green connected), its endpoint, and the number of log events since you last looked at it.
- **Hex editing of the payload** (Client and Server): tick *Hex* and type `02 41 42 03`. Binary files are
  loaded and sent byte-exact.
- **Sharp on scaled displays** (the program is DPI aware), a new icon, and the window comes back where it
  was closed.
- Command line: `TcpTools.exe /tab:client|server|relay` plus the tools' switches
  (`/ip: /port: /autoconnect`, `/port: /autostart /echo /logfile:`).

### Fixed

- Closing the program, a quick reconnect, or stop followed by start could crash or leave a tool confused:
  every network thread is now stopped and waited for.
- Client: a connect can be cancelled; "timeout 0" really waits; a failed connect says why
  ("connection refused"); Keep Alive really switches keep-alive on.
- Server: sending no longer freezes the window when the peer stops reading; echo, statistics and the log
  agree with each other; UDP keeps working after a peer has gone.
- Relay: nothing is lost, repeated or reordered when auto-forward is switched while data flows; Forward
  keeps what could not be sent; the target field keeps its address.
- Received data: zero bytes no longer cut the text, the text and hex views always show the same bytes, the
  hex view keeps its place while data arrives, and memory use is bounded.
- Errors from the network go to the log and the status line instead of a message box in front of your work.
- F1 works wherever the focus is; the help texts and tooltips describe what the program really does.

### Notes

- IPv4 only. TCP server and relay serve one client at a time.
- The file is not code-signed: Windows SmartScreen may ask before the first start.
