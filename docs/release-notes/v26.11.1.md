## TcpTools 26.11.1

### New

- **IPv6.** The client and the relay connect to IPv6 addresses and to names that resolve to them; the
  server and the relay listen on IPv4 and IPv6 at the same time. Type `::1`, `[fe80::1%12]` or
  `[2001:db8::5]:502` where a host goes — `host:port` and `[address]:port` fill both fields.
- **Waiting clients are visible.** The TCP server and the relay still serve one client at a time, but a
  second client no longer waits unseen: the tab shows how many are waiting, the log says when one starts
  waiting and when it gets its turn.

### Fixed

- **The window stays responsive under load.** Received data reaches the window through one bounded queue
  and is shown in a few steps instead of chunk by chunk: after a megabyte burst the program reacts at once
  (it could be busy for seconds), and no received chunk is left out of the views when the window is busy.
- **Auto-Disconnect keeps the reply.** The client now waits for the answer before it disconnects (until
  the peer closes, or shortly after the last received byte); the reply to a one-shot request used to be
  cut off.
- **Disconnect and Stop return at once** also while a host name is being looked up.
- **A port belongs to one server.** The server and the relay take their listening port exclusively; a
  second program — or a second TcpTools — gets a clear "port in use" instead of silently sharing it.

### Release

- The published file is now the one the end-to-end tests ran against: the release workflow builds,
  tests, packages and publishes in one run.
- The release tooling signs `TcpTools.exe` when a code-signing certificate is configured. This release
  is **not signed** (no certificate is configured yet): Windows SmartScreen may ask before the first start.
